# 文件整理与交付

## 目录约定

沿用使用者已建立的结构。没有现成约定时，建议“一期一个文件夹，发布文件在外层，过程资料放在制作素材”。项目根位置由用户指定，不写死电脑用户名或桌面路径。

```text
001_确认后的标题/
├── 001_确认后的标题.mp4
├── 05_发布文案.md
├── 06_封面_横屏.png
├── 06_封面_竖屏.png
└── 制作素材/
    ├── 01_原始口播.mp4
    ├── 02_剪辑无字幕.mp4
    ├── 04_最终字幕.srt
    ├── 剪辑记录.md
    ├── MG源文件或工程目录/
    └── 制作状态.md
```

这只是路径示例，不创建空媒体、空字幕或虚假的工程凑齐目录。实际只保留本期已产生的文件。复杂 MG 工程可以保留其内部依赖结构，不强行拆散为单层素材。

## 命名和版本

- 新一期先检查用户指定项目根中的已有编号，避免重号。已有项目沿用原编号，改标题或重新导出不重新编号。
- 标题未确认时使用准确编号和暂定用途名，标注暂定；标题确认后，在下一次保存或整理时同步规范目录与发布文件名。
- 项目目录与最终视频的编号、完整标题保持一致。为文件系统不支持的字符做必要替换，并记录原始显示标题；不自行缩写标题。
- 无字幕预览、原始口播与发布成片分清用途；多版本加用途或版本后缀，不覆盖同名文件。
- 改名前确认文件属于本期且目标无冲突，改后核对清单、文件大小和内容，更新有效引用。视频移动或改名时可用哈希核对未改变媒体内容；它只能证明字节一致，不能代替观看检查。
- 原片保留。删除、覆盖或清理旧稿要有用户明确授权；共享资源不随本期修改。

## 续做记录

在实际发生阶段变化时维护制作状态，避免重复制作：

```text
本期：编号与当前标题（注明暂定或已确认）
来源：当前素材或编辑器项目的可识别位置
剪辑：未开始 / 待确认 / 已确认；对应版本
MG：不需要 / 方案待确认 / 制作中 / 待确认 / 已确认
字幕、文案、封面：分别记录阶段与版本
导出：未导出 / 待用户导出 / 已核验实际文件
下一步：具体待办及其前置条件
```

这是字段示意，按本期真实状态填写，不把“已确认”示例原样复制。制作记录可能含私有路径和项目标识，应保存在使用者的项目中，不回写公开 Skill 仓库。

## 交付

先列出并核验实际产物。媒体能解码或播放、图片能打开、SRT 时间与版本匹配、文案采用确认稿；实际没有相应工具时说明未核验项。给出真实文件链接或编辑器预览，以及仍待用户确认、导出或发布的事项。

文件存在、剪辑加入时间线、用户确认和发布完成是不同状态。只报告有依据的状态，不编造制作时长、检查通过记录或平台发布结果。
